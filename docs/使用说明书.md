# Temu 违规商品下架助手 — 使用说明书

本说明书面向不熟悉编程的同事，讲的是怎么用这两个程序，不涉及代码。

## 一、这套工具是什么

一共两个独立的小程序，装在不同的机器上：

| 程序 | 装在哪 | 干什么 |
|---|---|---|
| **TemuDelisting.exe**（主机端） | 一台固定的主机 | 真正登录 Temu、扫描违规商品、执行下架，是核心程序 |
| **TemuDelistingSatellite.exe**（分机端，可选） | 各个店铺自己的小机器 | 不装 Chrome、不登录 Temu，只负责把"帮我扫描/下架"的请求丢给主机 |

核心流程固定是三步，**下架之前必须经过确认**，不会扫完直接自动下架（除非你在接口程序里主动选了"扫描并自动下架"，见第六节）：

```
扫描（抓取违规商品） → 审核（人工勾选确认要不要下架） → 下架（提交下架申请）
```

只有主机端能真正执行扫描/下架；分机端只是"远程按按钮"，实际干活的还是主机。如果只有一台机器在用，完全可以不装分机端，直接用主机端就够了。

## 二、主机端：安装与首次设置

### 2.1 安装

1. 确认这台电脑**已经装好 Google Chrome**（正式版，不是别的浏览器）。这是唯一的前提条件，不需要装 Python，不需要碰命令行。
2. 把 `TemuDelisting.zip` 解压到任意位置（建议不要放在中文路径特别深或者带特殊符号的目录下）。
3. 双击文件夹里的 `TemuDelisting.exe` 打开。

第一次打开会自动在 exe 同一层建一个 `data` 文件夹，这个文件夹存了账号、登录态、扫描记录，**千万不要删**，删了等于清空所有账号数据。

### 2.2 添加第一个账号

1. 切到「账号管理」标签页 → 点「+ 添加账号」
2. 填「显示名称」（自己起的名字，方便识别）和「店铺名称」（如果这个 Temu 登录下有多个店铺，这里填网页上显示的真实店铺名字，一字不差；如果登录下只有一个店铺，可以留空）
3. 点「打开专属登录窗口」——会弹出一个**真实的 Chrome 窗口**，在这个窗口里手动输入账号密码登录 Temu 卖家中心
4. 登录成功、看到卖家中心首页后，关掉这个窗口，回到程序里点确认

**为什么必须手动登录**：Temu 会直接拦截自动化程序发起的登录请求，这是网站自己的反爬虫机制，任何自动化工具都绕不过去，所以登录这一步永远需要人工操作。登录一次之后，程序会记住这个登录状态，不需要每天重新登录。

### 2.3 一个 Temu 登录、多个店铺的情况

如果你的手机号下面有好几个店铺，不需要重新登录好几次——用「+ 复制账号」，选一个已经登录过的账号作为来源，就能新建一个共用同一份登录信息的账号条目，只是店铺名称不同。

## 三、主机端：日常使用（扫描 → 审核 → 下架）

1. 「运行」页顶部选好「当前账号」，选「违规开始日期」「结束日期」，点「开始扫描」
2. 扫描会打开一个 Chrome 窗口自动翻页抓取，跑完之后自动跳到「审核清单」页
3. 审核清单页会显示三个数字：网页显示总数 / 实际抓取条数 / 去重后不同 SPU 数——这三个数字对不上是正常的（同一个 SPU 可能在不同国家/地区分别违规，会出现好几条），不用纠结，下架时程序会自动识别已经处理过的，不会重复下架
4. **黄色底色**的行是没见过的违规类型（"待人工判断"），默认不勾选，需要你自己核实清楚再决定要不要勾
5. 勾选/取消要下架的商品，点「保存审核结果」
6. 回到「运行」页，点「开始下架」——会弹一次确认框（这一步不可撤销，请确认清楚），确认后开始真实提交下架申请
7. 下架过程中「任务列表」会显示进度，可以随时点「停止」（会等当前商品处理完再停，不会中途打断正在提交的表单）

### 3.1 多账号同时跑

不同账号可以同时各自扫描/下架，互不影响，各自开独立的 Chrome 窗口。**唯一的限制**：同一个账号同时只能有一个任务在跑；另外，用「复制账号」建出来的、共用同一份登录信息的几个账号，因为背后是同一个 Chrome 登录窗口，**不能真的同时跑**（会互相冲突报错），这种情况系统会自动排队处理，不用手动干预。

### 3.2 「运行」页的一键清空

日志区和任务列表各有一个「一键清空」按钮：
- 日志清空只清界面上显示的内容，**磁盘上的日志文件不会受影响**，事后排查问题还是能在「账号管理」页的「查看日志」里找到完整记录
- 任务列表清空前，如果还有任务在跑会提示先等它跑完，避免正在运行的任务状态行错位消失

## 四、账号管理

「账号管理」页可以做的事：

| 按钮 | 作用 |
|---|---|
| + 添加账号 | 全新登录一个账号 |
| + 复制账号 | 跟已有账号共用登录信息，只是店铺名称不同 |
| 导入 Excel | 批量建账号"架子"（见 4.1），导入后还需要逐个登录 |
| Excel 格式说明 | 弹窗显示 Excel 需要哪些列 |
| 全选 / 取消全选 | 勾选框批量操作 |
| 编辑 | 改显示名称、店铺名称（单选） |
| 更新登录信息 | 登录过期了，重新走一遍登录流程 |
| 查看日志 | 看这个账号历次运行的完整日志文件 |
| 删除所选 | 批量删除勾选的账号（不可恢复） |

### 4.1 Excel 批量导入格式

表格第一行是表头，列名要写得跟下面完全一致（顺序无所谓，多余的列会被忽略）：

**必须要有的列：**
- **账号** —— 手机号，纯展示/分组用，**不是登录密码**，也不会被拿去做任何自动化操作
- **店铺数量** —— 这个手机号下一共几个店铺
- **店铺名称** —— 网页上真实显示的店铺名字，多个店铺用顿号、逗号或斜杠隔开，比如"SaveNest、Dwmane Shop"

**可以不填的列：**
- **全托管 / 半托管** —— 数量，会自动记进备注里
- **店铺编号** —— 内部编号，纯展示用
- **备注** —— 自己想写什么都行（谁负责的、什么时候接手的），会原样保留在导入后账号的备注最前面

导入进来的账号只有"架子"（名字、备注），**没有登录信息**，每个账号导入后还要单独用「+ 添加账号」或「+ 复制账号」手动登录一次。

> **关于密码：不要在这份 Excel 里存 Temu 登录密码，也不要指望能导入进这个程序。** 这套工具从设计上就没有、也做不到自动登录（Temu 会拦截自动化登录），密码导进来完全用不上，只会变成明文躺在共享表格和主机本地数据库里，是真实的泄露风险。密码这类信息只应该由知道它的人亲手敲进登录窗口，不应该出现在任何文件里。

## 五、常见问题：删除账号没反应

如果点了「删除所选」但界面上账号还在，一般是因为要删除的数据文件夹里有文件被占用（比如刚用完还没完全释放），导致删除卡了一下。现在的版本已经修复：**账号会先从账号列表里移除**（这个是权威判断），文件夹删不干净不会再卡住整个操作，界面必然会跟着刷新。如果还是遇到异常，请把「查看日志」里的内容发出来核对。

## 六、接口程序（局域网远程任务，可选功能）

如果你只有一台电脑在用，这一节可以跳过。这个功能是给"店铺在外地、不想给每台机器都装完整主程序"的场景用的。

### 6.1 工作原理

1. 你事先在一个**网络共享文件夹**（局域网内主机和分机都能访问、且有读写权限的位置）下面，给每个要开放远程操作的账号建一个子文件夹，**文件夹名字要跟「账号管理」页里的显示名称完全一致**
2. 分机端提交任务时，会往对应账号的子文件夹里丢一个请求文件
3. 主机端定时（每 10 秒）检查这个共享文件夹，发现新请求就自动处理，处理完把结果写回同一个文件夹
4. 分机端定时查这个结果，显示在自己的界面上

### 6.2 主机端设置

切到「接口程序」标签页：

1. 「共享文件夹路径」填那个网络共享路径（比如 `\\主机电脑名\共享文件夹名`）
2. 勾选「开启监听」
3. 「同时最多处理几个远程任务」——**默认 1，也就是一个一个排队跑**，不管几个账号同时提交请求，主机都会按顺序一个一个处理。等观察一段时间确认排队跑得动、想要更快，可以把这个数字调大（比如调成 3 就是同时最多开 3 个 Chrome 窗口跑不同账号）——**注意**：共用同一个 Chrome 登录的账号（用"复制账号"建的）永远不能真正同时跑，不管这个数字调多大
4. 点「保存设置」

页面下半部分是「待处理的远程任务」排队清单，显示还没开始处理的请求，可以用「上移」「下移」手动调整先处理谁，不是死板地按提交时间先来后到。

### 6.3 风险提醒：「扫描并自动下架」

分机提交任务时可以选两种操作类型：

- **仅扫描**：扫完的商品需要主机这边有人去「审核清单」页手动确认才会下架，安全
- **扫描并自动下架**：扫到的商品**全部自动确认、直接执行真实下架，不需要主机这边有人审核**，操作不可逆

这是经过明确讨论后按需求实现的——如果你不希望某个分机能跳过人工审核直接下架，让那边的操作人员**只提交"仅扫描"的任务**就行。

## 七、分机端：安装与使用

### 7.1 安装

1. 这台机器**不需要装 Chrome，不需要登录 Temu**——分机端只是写/读几个 JSON 文件，跟自动化完全不碰边
2. 把 `TemuDelistingSatellite.zip` 解压到任意位置，双击 `TemuDelistingSatellite.exe`

### 7.2 提交任务

1. 「共享文件夹路径」填跟主机那边**同一个**网络路径（填过一次会自动记住，下次打开不用重填）
2. 「账号」下拉框会自动列出共享文件夹里已经建好的账号子文件夹——**直接选，不要手打**，避免打错字（主机那边靠文件夹名字精确匹配账号，打错字的话请求会被直接跳过）；如果下拉框是空的，点「刷新账号列表」
3. 选「违规开始日期」「结束日期」
4. 「操作类型」选「仅扫描」还是「扫描并自动下架」（后者见 6.3 的风险提醒，选之前会有一次确认弹窗）
5. 点「提交任务」

### 7.3 查看结果

提交之后会出现在下面的「提交记录」表格里，状态一开始是"等待中"，每 5 秒自动查一次，主机那边处理完之后状态会自动变成"已完成"或"失败"，并显示统计数字（抓了多少条、去重后多少个 SPU、下架成功/需要人工跟进多少个）。

表格上方有「一键清空记录」——清空的只是这台机器上的本地显示记录，**不影响已经提交出去、主机那边可能还在处理的任务本身**。如果还有任务没查到结果就清空，这台机器会不再自动追踪它们的进度（结果文件本身还在共享文件夹里，不会丢）。

## 八、故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 双击 exe 没反应/报错"未检测到 Chrome" | 这台电脑没装 Google Chrome，装好正式版 Chrome 再试 |
| 提示"登录已过期" | 「账号管理」→ 选中账号 → 「更新登录信息」，重新走一遍手动登录 |
| 扫描完了但「审核清单」页是空的 | 「审核清单」页只跟着「运行」页当前选中的账号走，切一下账号下拉框到刚才扫描的那个账号；如果扫描是远程触发的，标签页文字会显示"审核清单（N 个账号待查看）"提醒你 |
| 远程任务一直显示"失败：程序遇到问题" | 大概率是这个账号跟别的账号共用同一个 Chrome 登录（用"复制账号"建的），同时被触发时互相冲突——把「接口程序」里的并发数调回 1，或者错开提交时间 |
| 分机账号下拉框选不到某个账号 | 共享文件夹底下没有跟账号显示名称完全一致的子文件夹，需要先手动建一个 |
| 想批量删账号 | 账号管理页勾选框 + 「全选」/「删除所选」，会有确认弹窗，删除不可恢复 |

## 九、安全说明（务必留意）

- **密码永远不落盘**：登录只能人工在真实 Chrome 窗口里完成，任何 Excel、任何这个程序的文件里都不应该出现密码
- **下架不可逆**：无论是主机手动点「开始下架」，还是分机触发「扫描并自动下架」，提交之后都无法撤销，请确认清楚账号和日期范围再操作
- **删除账号不可恢复**：会连同登录信息、历史记录一起删掉
- 「接口程序」开启监听后，共享文件夹里任何名字对得上账号的请求都会被处理，请只把共享文件夹的写入权限开放给信任的人
